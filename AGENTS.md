# AGENTS.md

Правила для людей и ИИ-агентов, которые работают с репозиторием Routeliner.

## Состав

| Папка | Содержание |
|---|---|
| routeliner/core | Расчёт без импорта QGIS: пикеты, ведомость, геометрия маршрута, сборка, события, эталонный пример |
| routeliner/layers | Переход от слоёв QGIS к ядру и динамические слои |
| routeliner/processing | Провайдер и инструменты Processing |
| routeliner/doc | PDF руководства, собранные из manual |
| manual | Исходный текст руководства, manual.md и manual_en.md |
| tests/core | Тесты ядра и перевода, запускаются без QGIS |
| tools | Сборка словаря перевода |

## Код

1. Ядро не импортирует qgis, а всё, что зависит от QGIS, лежит в папках layers и processing.
2. Каждая запись, которую нельзя поставить, попадает в таблицу ошибок с кодом ErrorCode. Пропуск записи без такой строки не допускается.
3. Коды ошибок и значения полей вроде rl_side не переводятся, переводится только rl_message.
4. Поля результата начинаются с префикса rl_, и имена этих полей не меняются между версиями без записи в CHANGELOG.md.
5. Новый инструмент получает номер группы и порядковый номер, например 2.03, одинаковый в Processing, меню и руководстве.
6. Имена полей не переводятся. Перевод полей делается псевдонимами. Словари ALIASES и PLAIN_ALIASES и выбор псевдонима лежат в routeliner/core/aliases.py и проверяются без QGIS, установка псевдонима на слой и запись его в файл - в routeliner/processing/common.py.
7. Псевдоним пишется и в сам GeoPackage, через GDAL AlterFieldDefn. Иначе он живёт только в проекте, и файл, открытый сам по себе, снова показывает латиницу. В файл идёт язык сборки, а слой, открытый инструментом, перекрывается языком интерфейса.
8. M-значения геометрии хранятся в ядре отдельно от координат, в RouteGeometry.measures, чтобы M не путался с Z. Пикетаж из M строит ChainageSystem.from_measures, а все инструменты получают его через общий параметр USE_M. Отдельной логики под M в инструментах нет.
9. Журнал работы ведёт routeliner/trace.py, файл routeliner.log лежит в папке профиля QGIS. Базовый класс инструментов сам пишет в журнал запуск, параметры, замечания, время и сбой со стеком, поэтому в новом инструменте ничего добавлять не нужно. Сбой кнопки меню или панели пишется в журнал и не роняет QGIS.
10. Записи журнала идут по-русски на любом языке интерфейса и в перевод не входят. Сборщик ключей tools/i18n_keys.py пропускает строки внутри вызовов step, data, fail, write и _log.

## Перевод

1. Строки интерфейса пишутся по-русски и оборачиваются в tr() из routeliner/i18n.py.
2. Английские значения лежат в словаре EN в tools/make_translations.py. После правки строк словарь пересобирается командой `python tools/make_translations.py`.
3. Справка инструментов пишется по тем же правилам RULES.ru.md, что и руководство, и проверяется measure.py в полосе register. Поля результата в справке перечисляются по строке на поле, строкой с дефиса.
4. Тест tests/core/test_i18n.py проверяет, что у каждой строки есть перевод и совпадают подстановки в фигурных скобках.

## Руководство

1. Руководство и оба README пишутся по правилам RULES.ru.md и RULES.en.md из репозитория [agents-md-document-project](https://github.com/Valery35/agents-md-document-project).
2. Каждый текст проверяется скриптом measure.py из того же репозитория в полосе note, и нарушений в отчёте быть не должно.
3. Источником каждого числа служит параметр по умолчанию в коде или прогон демонстрационного примера с указанием зерна и версии QGIS.
4. Сравнение со штатными инструментами QGIS ставит факты рядом, без оценок.
5. Русская и английская версии совпадают по разделам и таблицам.
6. PDF собирается pandoc с движком xelatex в routeliner/doc/Routeliner.pdf и routeliner/doc/Routeliner_en.pdf. Заголовок, подзаголовок и версия передаются файлом `--metadata-file`, в тексте YAML-шапки нет. Кириллица через `-M` в командной строке портится, поэтому только файл.

```
pandoc manual/manual.md -o routeliner/doc/Routeliner.pdf --pdf-engine=xelatex --toc --metadata-file=ru.yaml -V fontfamily=fontspec -V mainfont="DejaVu Serif" -V geometry:margin=2cm
```

   В ru.yaml лежат title: Routeliner, subtitle «События на маршрутах и пикетаж для QGIS. Руководство пользователя», date с номером версии вида v0.5.0 и lang: ru. Английская сборка берёт en.yaml с subtitle «Route events and chainage for QGIS. User manual» и lang: en.

## Проверка перед выпуском

1. Тесты ядра, запущенные командой `python -m pytest`, проходят без ошибок.
2. Инструмент 1.01 в QGIS даёт «ПРОВЕРКА ПРОЙДЕНА» на русской и английской локали.
3. Версия совпадает в metadata.txt, CHANGELOG.md, подвале README и руководства.
4. В архив модуля входит только папка routeliner, без tests, tools и manual.
5. Перед правкой рабочая копия сверяется с последним коммитом в C:\Dev\routeliner, потому что над модулем могут работать несколько сессий. Чужой коммит не перезаписывается, правка ложится поверх него под следующим номером.
6. В живом QGIS пользователя методы классов Qt не подменяются даже на время проверки. Подмена QDialog.exec 25.09.2026 сломала окна всех модулей до перезапуска QGIS. Окно проверяется в отдельном процессе QGIS или снимком уже открытого окна.

## Выпуск

1. Номер версии, уже отданный в архиве или коммите, закрыт, и следующая правка получает следующий номер.
2. В Dropbox\ИИ\Routeliner лежат два архива без номера версии в имени. Архив routeliner.zip идёт в каталог модулей QGIS, архив routeliner_repo.zip повторяет репозиторий.
3. Тег выпуска на GitHub пишется без буквы v, например 0.4.3.
4. На каждую версию, загруженную в каталог модулей, на GitHub заводится релиз с тем же номером и архивом модуля.
